# 记忆与上下文管理 v2

本模块已接入当前聊天入口，不只是保留在旧客服代码中。定位为**单用户、本机运行的结构化记忆管理**，不是带登录隔离的云端长期记忆服务。

## 分层设计

| 层级 | 保存内容 | 使用边界 |
|---|---|---|
| 宠物档案 | 独立ID、名字、物种、年龄、体重、信息来源与更新时间 | 跨事件保留；超过30天的年龄/体重不直接复用，重新追问 |
| 当前事件 | 症状、持续时间、次数、已知信息、追问、未排除风险 | 按宠物隔离；“新情况/新事件”等明确表达会重建事件，不复用旧症状 |
| 有界上下文 | 最新有效档案、结构化事件摘要、当前消息 | 不把全部历史逐轮拼接回模型；被更正的字段不从旧文本重新抽取 |
| 本机持久化 | SQLite中的档案和可恢复会话 | 用户显式开启后才写入；新会话只自动载入稳定档案，历史症状仅在主动恢复旧会话时恢复 |

相关代码：[memory.py](../app/memory.py)、[memory_store.py](../app/memory_store.py)、[chat_session.py](../app/chat_session.py)。

## 自动切换和纠错

- 例如“狗叫豆豆，3岁，今天食欲不好”“另一只猫叫咪咪，1岁，今天拉稀”“回到豆豆”会建立或切换独立档案。
- 两只已登记的狗同时存在时，仅说“我家狗吐了”不会猜是哪只，而是确认名字。一个消息涉及多只宠物时先要求分别说明；当前消息的紧急提示不会等身份确认。
- 单独的订单/商品话题暂时脱离健康事件，不把旧症状带进物流回复；之后可说名字继续。
- “年龄说错了，不是3岁，是5岁，体重实际5公斤”会更新有效字段并留下更正记录。明确的症状替换也会更新当前症状。
- 尚未排除的急症风险单独保留，不会因为普通历史折叠而丢失。仅一句否认不自动撤销风险；这是保守处理，可能导致过度提示。明确开始新事件会重置旧事件。

## 摘要、长度与Token预算

摘要为**基于已提取事实的结构化摘要**，不是LLM自由撰写的摘要。未抽取的闲聊细节不保证长期记住。

- 每只宠物保留最近最多6条、合计不超过8000个UTF-8字节的用户原文，其余折叠为当前结构化状态；界面保留最近40条消息。
- 单次用户输入最多6000个UTF-8字节；超限会明确要求分段，仍先检查该消息中的紧急信号，不静默截断。
- 当前事件组装上下文最多10000个UTF-8字节。超限不伪装成功，也不悄悄删除关键风险。
- 所有Hy3请求统一检查系统提示词和用户载荷总预算，默认24000代理单位，其中为输出预留4096，并计入256的消息结构余量。
- **这是保守的字节代理量，不是Hy3官方tokenizer的精确计数或数学保证。** 真正的token用量以API返回的usage为准；每次请求同时记录预算代理量与真实usage。

## 如何开启跨会话保存

1. 展开侧栏“记忆管理”，阅读明文、本机存储说明，勾选“在本机保存宠物档案和会话”。
2. 每轮自动保存；也可点击“立即保存当前会话”。刷新或重启后，重新开启保存开关会载入稳定档案。
3. 要继续旧事件，选择历史会话并点击“恢复所选会话”。不恢复旧会话时，不把其临时症状当作当前症状。
4. 关闭开关会停止后续保存，但不删除已有记录。要删除，在确认框勾选后点击“清除本机记忆”；这是永久清除本地数据库中的会话和档案。

存储位于`.local/memory.sqlite3`，目录已加入Git忽略。不保存API密钥配置，不上传远端；但是用户若在聊天里主动输入敏感文字，它可能随聊天内容被本地保存。数据未加密，同一电脑上的其他使用者可能读取。请保持服务监听127.0.0.1，未接入登录或多用户授权，不要直接对公网开放。

## 尚存边界

名字、物种与纠错表达主要依赖显式文本和有限规则；别名、复杂指代、无标点纠错或同时叙述多个事件可能仍需确认。保存的年龄不是出生日期，30天失效策略也只是工程规则。没有向量检索、跨设备同步、加密、账户权限隔离或人工临床校验。
