# 记忆和上下文管理

这部分已经接入现在的聊天页面。我没有沿用旧客服的 Redis 会话层，而是把宠物档案、当前事件和本机保存拆开处理。目前按单用户、本机使用来设计，还没有云端账户隔离。

## 信息怎么保存

| 层次 | 保存什么 | 什么时候使用 |
|---|---|---|
| 宠物档案 | ID、名字、物种、年龄、体重、来源和更新时间 | 不同事件之间保留；年龄、体重超过 30 天会重新问 |
| 当前事件 | 症状、持续时间、次数、补充信息、追问和未排除的风险 | 每只宠物单独保存；明确说“新情况”“新事件”会重建 |
| 模型上下文 | 最新有效档案、结构化事件摘要和当前消息 | 不再把全部历史一轮轮拼接，被更正的旧字段不重新抽取 |
| 本机数据库 | 档案和可以恢复的会话 | 用户开启保存后才写入；新会话只自动继承稳定档案 |

代码在 [memory.py](../app/memory.py)、[memory_store.py](../app/memory_store.py) 和 [chat_session.py](../app/chat_session.py)。

## 换宠物、换话题和纠错

例如先说“狗叫豆豆，3岁，今天食欲不好”，再说“另一只猫叫咪咪，1岁，今天拉稀”，系统会建立两个档案。之后说“回到豆豆”可以切回去。如果已经有两只狗，只说“我家狗吐了”，系统会先确认名字，不直接猜。一个消息涉及多只宠物时会要求分别说明，不过当前消息里的紧急提示不会等身份确认后才给出。

单独问订单或商品时，会暂时离开健康事件，避免物流回复混入旧症状；之后仍可以通过名字继续咨询。

用户可以说“年龄说错了，不是3岁，是5岁，体重实际5公斤”。系统更新有效字段，也留下更正记录。明确替换症状时同样会更新。尚未排除的紧急风险单独保存，不随历史压缩丢失；仅一句否认不会自动撤销风险。这种处理比较保守，也可能反复提示。明确开始新事件才会重置旧事件。

## 历史变长后怎么处理

我用的是已提取事实组成的结构化摘要，不是让模型自由总结。因此能保留已识别的档案和事件信息，但不能保证长期记住所有闲聊细节。

当前限制如下：

- 每只宠物保留最近最多 6 条用户原文，总计不超过 8000 个 UTF-8 字节，其余信息折叠到结构化状态；页面保留最近 40 条消息。
- 单条输入最多 6000 个 UTF-8 字节。超限时要求分段，不静默截断；仍先检查消息里的紧急信号。
- 当前事件组装的上下文最多 10000 个 UTF-8 字节。超过限制会提示问题，不悄悄删掉关键风险后继续。
- Hy3 请求统一检查系统提示词和用户内容的预算。默认 24000 个代理单位，其中预留 4096 给输出，另计 256 的消息结构余量。

这里的预算是按字节数保守估算，不是 Hy3 官方 tokenizer 的精确计数，也不能保证任何请求都不会超限。每次调用同时记录估算值和 API 返回的真实 usage，便于对照。

## 怎么开启本机保存

1. 展开侧栏“记忆管理”，阅读存储说明，勾选“在本机保存宠物档案和会话”。
2. 开启后每轮自动保存，也可以点“立即保存当前会话”。刷新或重启后，重新开启会载入稳定档案。
3. 如果想继续旧事件，选择历史会话，点“恢复所选会话”。不恢复时，旧症状不会当成现在的情况。
4. 关闭开关只停止后续保存，不删除已有数据。要删除，需要勾选确认框，再点“清除本机记忆”；这会永久清除本机数据库里的档案和会话。

数据在 `.local/memory.sqlite3`，该目录已加入 Git 忽略，不会随仓库上传。数据库不保存 API 密钥配置，但如果在聊天里输入敏感内容，它可能随会话一起保存。数据库没有加密，同一电脑的其他使用者可能读取。

本机保存不等于所有处理都离线：在线模式下，相关上下文仍会发给 Hy3。当前没有登录或多用户授权，请保持监听 `127.0.0.1`，不要直接开放到公网。

## 做过哪些测试

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_final_submission.py tests/test_memory.py -q
.\.venv\Scripts\python.exe scripts/validate_memory_live.py
```

28 项聚焦测试覆盖了宠物隔离、同物种歧义、数值和症状更正、话题切换、旧事件清理、长历史风险保留、超长消息、请求预算、档案过期，以及 SQLite 和界面的保存、恢复、清除。

另外用四轮构造消息做了真实 Hy3 调用验证，结果保存在 `results/memory/live_validation.json`。这是单独的记忆检查，没有并入原来的七维批量评测；`results/final/` 仍保留原实验。

## 还需要完善的地方

名字、物种和纠错识别主要依赖明确表达和有限规则。复杂别名、指代、无标点纠错，以及一句话说多个事件时，仍可能需要确认。保存的年龄也不是出生日期，30 天重新确认只是当前的工程规则。

跨设备同步、加密、多用户权限和向量检索还没做。四轮调用和这些测试不能覆盖所有自然语言情况，也没有兽医或临床验证。
