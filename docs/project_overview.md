# PetSupport-Bench 项目介绍

个人参赛作品｜犀牛鸟开源·混元大语言模型实战任务一｜非腾讯官方项目

## 一、我想解决什么问题

我这次做的是一个基于 Hy3 的宠物咨询 Agent，并为它设计了一套回答质量评测方法。项目是在之前的宠物商城客服工程上改造的，没有训练或微调模型。

我选这个场景，是因为用户不一定会把问题分得很清楚。比如问“狗粮怎么还没到”的同时，又提到狗刚刚误食了东西。如果客服只处理订单，就可能忽略后半句。我的想法是让系统自己识别这些诉求，先回应已识别的风险，信息不足时继续追问，最后整理出主人能看懂的建议和就诊准备信息。

这类回复没有唯一标准答案。回答流畅，并不一定说明它识别对了风险、问全了信息，或者没有越过用药边界。所以我把工作分成两部分：一部分是把应用做出来，另一部分是检查怎么评价它，以及评分方法会在哪些地方出错。

项目只做健康科普和就诊准备，不替代兽医诊断，也不提供处方或药物剂量。

## 二、现在怎么使用

用户直接在聊天框说情况，不用先选问题类型或填档案。例如先说“狗叫豆豆，3岁，今天食欲不好”，再回答追问；如果年龄说错了，可以直接更正。换成“另一只猫叫咪咪”时，系统会建立或切换档案，指代不清楚时会再确认。

```text
输入消息
  → 确认宠物和当前话题
  → 整理档案、当前事件和更正后的信息，控制上下文长度
  → 判断意图，检查已知紧急风险
  → 追问或生成就诊准备报告
  → 检查输出，显示调用情况和记忆变化
```

Hy3 用于部分意图判断、追问回复的信息提取、报告文字整理，以及离线评测中的评分。有些步骤由规则完成，所以并不是每轮都调用模型，页面会显示实际调用情况。

现在还没有连接真实商城后台。订单问题只能说明需要联系商城客服核实，不能实际查单或转人工。

## 三、我做了哪些部分

| 部分 | 目前的实现 | 代码位置 |
|---|---|---|
| 聊天界面 | 连续对话、追问、报告下载、调用记录 | `streamlit_demo.py`、`app/chat_session.py` |

| 记忆管理 | 按宠物和事件保存事实、更正信息、生成结构化摘要、限制上下文 | `app/memory.py`、`app/chat_session.py` |

| 回答评测 | 七维评分标准、Hy3 评审和规则检查、逐条记录 | `prompts/final_judge.md`、`eval/final_judge.py`、`scripts/final_eval.py` |
| 方法验证 | 好中差排序、重复评分、伪引用和评分指令攻击测试 | `scripts/validate_final.py` |

知识库目前只有 8 条带具体来源的简短内容，用关键词匹配。记忆摘要也是根据已提取的事实整理，不是让模型自由概括所有历史。上下文预算用字节数保守估算，真实 token 用量另记 API 返回值。

## 四、评测做了什么，结果怎么样

我设计了七个维度：风险回应、分流、信息处理、证据、安全边界、行动完整性和表达。每维 0–4 分，并给出具体判定条件。如果遗漏特定紧急行动或命中危险输出规则，总分会被限制在 39 分以内。生成和评分用的是同一 Hy3，评分时不提供配置名。

批量实验用了 100 条构造样本，共 39 种不同表达，其中混合意图、诱导和长文本干扰占 25 条。这些不是 100 个真实用户，也没有经过兽医标注。

| 配置 | 做法 | 有效评分数 | 平均分 |
|---|---|---:|---:|
| A0 | 直接让 Hy3 回复 | 100 | 83.70 |
| A3 | 规则、追问、知识卡片与 Hy3 配合 | 100 | 78.78 |

A3 的总分没有超过 A0。拆开看时，我发现既有应用的问题，也有评分方法的问题：例如 A0 有 15 条回答只因为规则命中而被限分，其中出现了把长句里的“禁止用药”误判成“建议用药”的情况。A3 的 4 次闸门触发则来自模型评审。因此，我没有把总闸门次数从 17 到 4 当作安全性提升的结论，原分数和分歧记录都保留了。

为了检查评分方法，我另外构造了 4 种场景的好、中、差和对抗回答，共做了 48 次评审。4 种场景都排出了好＞中＞差的顺序；同一回答重复评分的平均总体标准差是 2.048，波动最大的一份是 11.31。它说明评分器能区分这几组明显不同的回答，但边界样本仍可能不稳定。

这里还没有人工或兽医一致性验证。同一模型既生成又评分，也可能有共同偏差，所以目前只能讨论这批构造样本上的表现。

## 六、目前完成的和还没做的

目前项目已经能运行，聊天、信息追问和记忆管理也都接上了。代码、测试样本、评测结果、分析报告和演示视频已经放到 GitHub，运行步骤写在 README 里。密钥和本机聊天数据没有上传，依赖按说明安装即可，具体见[代码与文件说明](submission_scope.md)。

这一版主要做宠物咨询和回答质量评估，还没有接真实订单、物流、库存和人工接管。记忆保存在本机，没有做多账号、跨设备同步和数据加密；上下文长度仍是估算，知识库也比较小。

测试中还发现了规则漏检、误报，以及名字、别名、指代和纠错需要进一步确认的问题。目前没有兽医人工复核，也没有临床有效性验证。它是能运行、能检查结果的参赛原型，距离真实上线使用还有工作要做。

下一步我想先补复杂多轮对话，用独立的校准样本检查评分规则，再改已经发现的误判。有合适的人员和授权条件后，再安排人工复核。

## 七、如何查看和运行

[README](../README.md)里有安装和启动命令。不配置 API 也能先用离线规则看交互；想检查真实模型调用，需要自己填写有效密钥。

当前应用的测试命令是：

```powershell
python -m pytest tests/test_final_submission.py tests/test_memory.py tests/test_eval_artifacts.py -q
```

结果表对应的原始输出在 `results/final/`，记忆测试在 `results/memory/`。脚本有缓存或防覆盖处理，如果要重新调用模型，需要留意运行目录和提示，也会消耗 API 额度。

我希望这个项目能说明的不只是“模型能回答”，还包括回答哪里出了问题、评分为什么这么打，以及这套评分方法自身还有哪些地方需要改进。
