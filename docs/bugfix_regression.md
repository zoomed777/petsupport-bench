# 混合咨询漏掉健康描述的修复记录

## 当时的问题

录制演示时，输入：

> 换的猫粮什么时候到？我家猫最近食欲不好

页面只解释了不能查订单，没有追问猫的情况。检查后发现，旧规则识别了“什么时候到”和“猫粮”，却没识别“食欲不好”，因此提前按订单问题返回。这次不是 API 超时，这条路径本来就没有调用 Hy3。

## 我改了什么

我让路由复用症状提取词表，避免两个地方用不同的词表。同时补了“食欲不好”“食欲不佳”“胃口不好”“胃口不佳”“没胃口”“吃得少”等表达。

混合咨询进入追问时，页面会说明已经识别出健康描述，也会交代目前不能查询订单。这次修复补上了已发现的遗漏，不过关键词规则仍覆盖不了所有说法。

## 修复后怎么检查的

当时运行 `python -m pytest tests/test_final_submission.py -q`，10 项通过。新增测试包含用户原句和 5 种相关表达，纯订单问题仍走订单分支。

Streamlit 离线测试里，原句会显示年龄、持续时间和精神状态 3 个问题；补充“成年，3岁”“今天上午开始”“精神正常”后，会生成包含食欲下降的报告，页面没有异常。这部分检查的是交互流程。

另外用同一原句和补充信息做了一次真实 Hy3 检查：路由为 mixed，生成报告，剩余追问 0 个；记录到模型调用 1 次，错误 0 个，拦截字段 0 个。它只是一个具体输入的连通性检查，没有计入批量成绩，也不是医疗有效性验证。

## 和原实验的关系

`results/final/` 对应提交 `6368460`，原分数没有改。这次修复没有重新跑完整批量实验，所以旧分数不代表修复后的版本。

代码指纹变了以后，`final_eval.py` 会开始新一轮结果。如需重跑并保留原汇总，可以加 `--out results/新目录名`，单独保存。
