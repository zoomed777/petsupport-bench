# 聊天交互说明

现在的入口是一个聊天框，用户自己描述情况，系统判断类型并追问，不再让用户先选场景或填档案表。内部仍是规则和 Hy3 配合，主要处理本项目的宠物咨询场景。

## 一轮对话里发生什么

1. `ChatSession` 接收消息，整理当前宠物和事件，处理流程自动判断意图。
2. 缺信息时，问题直接作为助手消息显示。用户在同一个输入框继续回答。
3. 年龄、次数、持续时间等由规则提取；在线追问还会调用 Hy3，但只接受最新消息中确实出现的原文片段，不让模型自行补全。
4. 紧急信号会在信息提取前检查，不等用户答完全部问题。
5. 每轮保留模型调用、错误和规则路径，报告可以下载。开始新对话会清除事件上下文，保留稳定宠物档案。

后来补上的宠物切换、纠错、上下文预算和本机保存，见[记忆管理](memory_management.md)。

## 初版做过的检查

聊天初版对应 `8b66a0e`。当时通过了 13 项聚焦回归测试，覆盖纯聊天追问、用户原句、一次或分次补充、历史保留、新会话清空、拒绝无原文依据的提取，以及紧急描述打断追问。浏览器也检查了首次消息自动识别和显示追问。

真实 Hy3 两轮检查使用了下面的输入：

- 第一轮：“换的猫粮什么时候到？我家猫最近食欲不好”。结果识别为 mixed，提出 3 个问题。
- 第二轮：“它3岁，今天上午开始，精神还可以。”结果生成报告，剩余问题为 0；这一轮记录了信息提取和生成两次调用，错误为 0。

## 现在还要注意什么

当前支持明确的名字、物种切换和按宠物保存信息，但复杂指代、同名和一句话涉及多只宠物仍可能需要确认。规则和模型提取都可能出错，所以报告中的信息还需要用户核对。真实查单、转人工、诊断、处方和剂量建议都不在当前能力范围内。

记忆升级有另外的 28 项测试和四轮真实调用记录，不能把初版两次调用的情况套到所有新流程上。聊天改动也没有重跑整套批量实验，`results/final/` 仍对应 `6368460`。

后来补的[多轮测试](multiturn_report.md)覆盖了 14 组、55 轮，并修复了两处串档问题。加上缓存和回归检查后，当前测试共 62 项。新增在线记录单独保存，仍不与原单轮评分合并。
