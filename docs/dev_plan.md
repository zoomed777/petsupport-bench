## 哪些地方调整了

### 应用流程

最初想继续走旧 ReAct 和商城工具链，后来以独立 Streamlit 聊天作为演示入口。现在由系统判断问题类型，用户在同一个输入框补充信息。还没有真实查单或人工接管，不需要额外启动 Java 商城。

应用部分完成了意图判断、信息提取与追问、已知风险规则、知识卡片、结构化报告和输出检查。录制时发现“食欲不好”被当成纯订单问题，又补了词表和原句测试，见[修复记录](bugfix_regression.md)。

### 知识与数据

原计划的 120 条知识没有完成，最后优先保留了 8 条来源明确的简短内容。100 条样本共 39 种不同表达，包含模板重复和档案变体，不是真实用户工单集。

最初提到的种子样本、模拟分数和旧四配置结果都属于开发过程，最终结论只使用 `results/final/`。

### 评测和验证

原计划三个视角评分、人工仲裁、四配置消融，最后收缩为 A0/A3 对比，以及好中差、重复评分和对抗验证。

完成了 200 条有效评分、48 次方法验证。没有请两位标注者评分，因此没有 Kappa 或人工相关系数。固定温度也没有消除所有波动，最不稳定的回答三次评分差异仍明显。

### 后来补的记忆

聊天可以连续输入后，我又补了按宠物和事件保存信息、纠错、结构化摘要、请求预算和本机 SQLite 保存。完成了 28 项聚焦测试及 4 轮真实 Hy3 验证，记录在 `results/memory/`。

这部分晚于批量实验和视频，不能直接沿用原批量成绩说明新版效果。

## 开发时遇到的问题怎么处理

| 问题 | 这次的处理 |
|---|---|
| API 不稳定或暂时不可用 | 离线规则用于检查交互；真实实验另行运行，调用错误单独保存 |
| 模型输出不符合格式 | 校验返回值，保留错误并允许重试 |
| 评分波动 | 固定输入和提示词，对同一回答重复评审，报告实际波动 |
| 没有人手做人工标注 | 本次不报告人工一致性，说明这一缺口 |
| 原计划范围太大 | 先完成 A0/A3 和可检查的原始记录，未完成部分明确列出 |
